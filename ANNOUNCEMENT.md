# Vue Tailwind Datepicker is becoming CodeRocket UI

Vue Tailwind Datepicker started with a focused problem: make dates easier to work with in a Vue application. Thank you to everyone who used it, reported an issue or contributed.

The next step is **CodeRocket UI**: React and Vue component libraries you can customize as one design system, keep as editable source and share with coding agents. [Try the visual builder](https://ui.coderocket.app) or explore the [React](https://ui.coderocket.app/docs/components) and [Vue](https://ui.coderocket.app/docs/vue/components) documentation.

This repository keeps its stars, issues and history. Its active source now includes **48 components and 26 blocks for each framework**, the design-system engine, shared specifications, CLI, read-only MCP server and documentation. That foundation is open source under MIT. The hosted Studio, accounts and AI service are maintained privately.

## What changes for datepicker users?

The historical Vue datepicker is **frozen and no longer maintained**. Its npm package, `@coderocketapp/vue-tailwind-datepicker`, stays available. Its MIT source and original attribution are preserved in [`legacy/vue-tailwind-datepicker`](legacy/vue-tailwind-datepicker), and [its documentation](https://vue-tailwind-datepicker.com) stays online.

Existing applications do not need to change their imports because the repository changed its name. The new [Vue DatePicker](https://ui.coderocket.app/docs/vue/components/date-picker) is part of a broader native Vue library and has its own API. Migration is deliberate, not an automatic package upgrade.

No further fixes, features or package releases are planned for the historical component. Its MIT source remains available to adapt or fork.

## Why this direction?

A useful component library needs consistent tokens, behavior and source across an application. CodeRocket UI puts those rules in an explicit model that developers and coding agents can inspect. The visual builder applies them across components; CLI and MCP retrieve the same saved library in its chosen framework.

The public core works locally without a Studio account or AI provider. It is distributed here as source; workspace names are not a claim that new packages have been published to npm. React uses Base UI and Vue uses Reka UI, with native framework APIs. Svelte and SolidJS remain planned.
